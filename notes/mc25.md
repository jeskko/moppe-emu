# Mobira MC25 TVL/PTL

Status (2026-10-02): runs the OH5NXO/OH3NWQ ham firmware `mc25.asm` v3.6
(25 kHz and 12.5 kHz builds, byte-identical to the released binaries)
through its README's first-time setup and normal use. Hardware facts and
sources: the firmware repo's `notes/mc25.md`.

## Layers

| Layer | Files | Notes |
|---|---|---|
| CPU | `cdp1802.c` | CDP1802 at 2.24 MHz (the Talkman core; new `inta` callback for the interrupt acknowledge) |
| Board | `mc25.c` | KL1 memory map, binary-decoded ports OUT 1/2/3/5/7, INP 4/6, 1 ms interrupt, watchdog on INP 4, TV1 CCIR decoders/encoder at digit level, soft-UART line on /EF2, Q edge capture |
| Handset | `cu41.c` | CU41: 16-cell display controller (14 tube cells + 2 LED cells), serial keypad |
| API | `mc25_api.c` → `libmc25.so`; `python/mc25emu.py`; `python/mc25tui.py` | display decoded with the firmware's code tables; `first_time_setup()` |
| Tests | `tests/mc25/` | `roms.py` builds the firmware from the reference mirror with its as06; `test_mc25.py` (16 scenarios) |

## Model

| Item | Model | Source |
|---|---|---|
| Clock | 2.24 MHz, 280 machine cycles per ms | firmware ("35 * 8 == 280 == 1 ms", "1200 bd one bit takes 233.33 cycles"); crystal in the parts list |
| ROM | 0000-3FFF (an 8 KB image mirrored); code EEPROM 4000-5FFF optional (`load_eerom`) | firmware EEPROMSTART; 27C64 / "27128 also fits" (mod text) |
| RAM | 1 KB at 8000-83FF (2 x TC5514), mirrored to BFFF | firmware RAM test covers exactly 8000-83FF; mirroring assumed |
| NOVRAM | X2212 256 x 4 at C000-C0FF, mirrored to FFFF; reads 0xF0 \| nibble; no STORE/RECALL modelled (the firmware issues none) | parts list, firmware |
| Interrupt | 1 ms request, cleared by the interrupt acknowledge | firmware tick counts; nothing programs or acks it in software |
| Watchdog | reset 0.1 s after the last INP 4 | assumed; every firmware loop does INP 4 |
| Ports | OUT 1 display/keypad bit-bang, synth P0, alarm; OUT 2 synth P8..P1; OUT 3 volume, TXON, earphone, squelch gate, tone; OUT 5 CCIR TX code (F = off), CCIR acks, mic; OUT 7 2000/3112 Hz, simplex, TX power; INP 4 hook, squelch, lock, PROGRAM, OFFICE, 1800 Hz, EV/ARP detect; INP 6 CCIR digits | firmware port definitions; manual's LOCAL-mode tables |
| Flags | /EF1 PTT (flag false = pressed), /EF2 serial RX (flag true = mark), /EF3 keypad SDI, /EF4 LOCAL | firmware |
| Hook | INP 4 bit 0 = 1 on the hook (cradle switch pressed); PTT then sends CCIR 8 (1747 Hz) instead of opening the mic | firmware `btnproc` |
| Display | bits MSB first on SDO at DPYCLK rise; bytes < 0x80 written at a cursor wrapping at 16, 0x6E = decimal point of the previous cell, >= 0x80 commands that home the cursor; /RST clears. Cells 0-13 tube, 14-15 LED codes (`ledtbl`) | inferred from `dpyinit` (AF C0 FE, 14 x '8', 2 LED codes, 14-cell banner) and the 16-byte frames; no data sheet |
| Keypad | SDI high while a key is held; after release each KEYCLK falling edge shifts out a 0 start bit and the 8-bit code LSB first | CU41 text (PX12) + firmware `keyproc` |
| CCIR RX | digits queued per decoder (EV, ARP); one presented (detect bit) until acknowledged, the next 100 ms after the previous | TV1 text, firmware `check_ccirs` |
| Serial | /EF2: 1200 baud 8E1, mark = flag true; the firmware wakes on a NUL, then reads characters until EOT/timeout; ENQ makes it send its LED byte + display text on Q | firmware `serint`/`sertell`, MobyDick level converter |
| Synth | f = bASEF + (OUT 2 + P0/2) x STEP (25, 12.5, 10, 20 kHz per build) | firmware tables; manual RX = 2 x (62.000 + n x 12.5 kHz) + 21.4 |

## Evidence

- Boot sequence as the README describes: tube test with all LEDs, banner
  "3.6", "PEPA" with the simplex LEDs on a blank NOVRAM; the first-time
  setup clears them.
- 1000 interrupts per second; CCIR TX tones 100 ms apart (BEEPTICKS in
  1 ms ticks); serial keys at 1200 8E1 accepted and the ENQ report
  decodes at 1200 baud, so the CPU clock and cycle timing agree.
- A corrupted ROM byte fails the checksum and ends in `haltit` until the
  watchdog resets it.

## Known limits
