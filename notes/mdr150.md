# Comarco MDR150 data radio

Status (2026-10-08): runs OH5NXO's HaMDR 174 (2012-09-17), the newest ham
firmware, from his open bootstrap.

The radio is a Comarco MDR Systems / Comarco Finland "Mobinet Data
Radio"; the logic board is by Telemic (1994), the radio was built by 3i
Security International (Italy). It is **not** a Nokia/Mobira product.
Hardware facts and sources are in the firmware repo's `notes/mdr150.md`.

**What works:**
- the console on serial port 1 (`hamdr $`);
- `perm` saving the configuration into the Am29F010;
- APRS out: the beacon is read back by decoding the PWM audio;
- APRS in: AFSK fed into the receiver is decoded by HaMDR's own MAC-unit
  software modem and printed in TNC2 format;
- digipeating: WIDE1-1 traced to OH3RDX*, with distant stations
  rejected by `digi_area`;
- KISS in both directions.

There is no use for the original Comarco firmware here. Neither it nor
the resident Comarco loader (0x20000-0x23FFF) is needed, since OH5NXO's
`bootstrap` replaces the loader.

### CPU core

- **Opcode table:** generated by `tools/cpu16tab.py` from
  `tools/cpu16_ops.json`, which is Table 6-36 of the Reference Manual,
  parsed.
  - The encodings agree with the Real-Time Systems hc16 assembler's table
    on every row.
  - The operand layouts of BCLRW/BSETW and BRCLR/BRSET come from the
    glossary pages.
  - Each opcode carries its CCR effect as masks.
- **Pipeline:** branches, BSR/JSR/RTS, SWI/RTI and the exceptions follow
  the +6 rule.
- **MAC unit:** includes modulo addressing (XMSK/YMSK), the EV/MV/SL
  overflow logic, TMER convergent rounding and saturation. RMAC runs one
  iteration per step, so interrupts can come between iterations.

### Chip modules

- **SIM:**
  - SYNCR clock;
  - chip selects decoded per access from CSPAR/CSBAR/CSOR: block, R/W,
    byte lane on 16-bit ports, port size, DSACK wait states;
  - ports C/E/F;
  - PIT;
  - software watchdog: on at reset, SYPCR write-once, $55/$AA service;
  - interrupt arbitration by level and IARB, with the spurious vector
    when no module wins.
- **Standby SRAM:** RAMBAH/RAMBAL, with RLCK.
- **GPT:**
  - prescaler (CPR write-once);
  - OC1-OC5 with pin actions and OC1M/D, CFORC;
  - IC1-IC4 edges;
  - TOF;
  - read-then-write-0 flag clearing;
  - the ICR vector with the IPA-elevated source;
  - PWM A/B with buffered duty.
- **QSM:** SCI with frame timing, TDRE/TC/RDRF/OR/IDLE and their
  clearing sequences, interrupts by QILR/QIVR; port QS. QSPI registers
  only.
- **ADC:** prescaler, conversion timing, single/scan, 4/8 conversions,
  single/multichannel, CCF/SCF/CCTR, the three result formats, port ADA
  digital reads.

### Board

- **Memory:** flash and RAM wired to the chip selects as on the
  schematic (see Model).
- **Am29F010 command set:** program, sector erase, chip erase,
  autoselect and reset. Operations complete at once.
- **Radio module:** 4094 and MB1504 on port F, TX keying, power level.
- **RX path:** audio, noise, RSSI and BUSY into the ADC.
- **TX audio:** PWMA duty changes logged while keyed.
- **Serial:** 4053 serial mux (SSEL), RS-232 handshake inputs, LEDs.

| Instruction timing | The summary table's clocks, plus for each access what it costs beyond two clocks. Program accesses are one per instruction word; a taken change of flow is charged a three-word refill. A misaligned word is two byte accesses. | CPU16RM 8 |
| Bus | Internal modules and the standby RAM take 2 clocks. External cycles take 3 + DSACK wait states, or 2 with fast termination; a word to an 8-bit port is two byte cycles. Flash runs with 6 wait states under the bootstrap and 2 under HaMDR, RAM with fast termination. | SIM manual 7.5 |
| Chip selects at reset | CSBOOT base 0, 512 KB, CSORBT 7B70 (13 waits), 8-bit port (DATA0 is low, since the flash is on D8..D15). The others are disabled. | SIM manual 7.9 |
| Byte lanes | On a 16-bit port, BYTE = 01 ("lower") asserts for the odd byte (D0..D7) and 10 for the even byte. The spec summary had it the other way. On this board CS0 (BYTE 01) is the write strobe of the RAM on D0..D7, and HaMDR runs, so this direction is confirmed. | schematic sheet 2 |
| Flash | OE = CSBOOT, WE = CS10, CE = /ADDR18, A0..A16. Under the final map it sits at 0x20000-0x3FFFF. At reset it also appears at 0 (A17 is not decoded), which is how the reset vector reaches the bootstrap. | schematic sheet 2 |
| RAM | Two 32 KB chips on A1..A15: OE = CS2, WE = CS0 (D0..D7) and CS1 (D8..D15). It is cleared at power-on. | schematic sheet 2 |
| 4094 | Shares CLK/DATA with the MB1504 and latches on SR_STB (PF1). Its outputs are active low: Q2 audio, Q3 PLL, Q4 VCO, Q5 IF/RX, Q6 TX, Q8 mute. TX is keyed = Q6 low with POWEL (PF5, the 4094 output enable) high. | hamdr.c RFCMD_*, pll_etc.s |
| MB1504 | Shifted MSB first, latched on PLL_STB (PF4). The last bit 1 selects the reference latch (SW, R14). The last bit 0 selects the N11/A7 latch. VCO = (64·N + A) · 12.8 MHz / R. On receive the VCO is the channel minus the 21.4 MHz IF; on transmit it is the channel. | pll_etc.s, hamdr.c vco_update |
| ADC inputs | AN0/2/4/6 carry the demodulated audio: 512 ± `audio_level` · signal while Q5 (IF) is on and audio is queued, otherwise noise of ± `noise_level`. AN1 is RSSI, AN3 BUSY, AN5 UNLOCK (high until both PLL words are loaded and Q3/Q4 are on). Port ADA bit 3 = BUSY, bit 5 = UNLOCK. | afsk.s, pit.s, pll_etc.s |

## Fidelity evidence

- **CPU tests:** the CPU unit-test programs pass.
- **Disassembler:** `cpu16dis.py` reproduces the assembler sources of
  the test programs and the bootstrap.
- **HaMDR in full:** HaMDR's GCC 2.8.1 code and its assembly modules run
  without illegal instructions or unmapped accesses. This covers every
  module's interrupts, the MAC filters of the modem, the flash
  programming routine run from RAM, and the console.
- **APRS out:** the APRS frames HaMDR transmits decode with `afsk.py`
  from the PWM duty stream.
- **APRS in:** frames encoded by `afsk.py` are decoded by HaMDR.
- **Synthesizer:** the channel words come out as 144.800 MHz on
  transmit and 123.400 MHz (= 144.800 - 21.4) on receive.

## Limits

- **SCI frames:** frame-level only, with no bit-level RXD and no break.
  The QSPI does not transfer, so an I2C LCD or keypad on the add-on
  connector is not modelled.
- **LPSTOP:** behaves like WAI. The GPT, SCI and ADC keep running, the
  PIT and the watchdog stop.
- **Bus monitor:** not modelled. An unmapped access reads FF and is
  counted (`unmapped()`).
- **Bus errors:** BERR is never raised.
- **Not modelled:** IRQ pins, external DSACK, the pulse accumulator
  input, PCLK.
- **Flash timing:** program and erase complete immediately, so DQ6/DQ7
  polling sees the result at once. Programming from code running in
  flash would therefore not fail as it would on hardware.
- **RX front end:** RSSI is a plain ADC value, and there is no squelch
  or BUSY model beyond what the API sets. Audio is the clean signal
  scaled, or uniform noise.
- **Comarco loader:** the resident loader is not modelled; the
  emulated flash holds OH5NXO's bootstrap in its place.
