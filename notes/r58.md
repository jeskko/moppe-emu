# Mobira R58 series (RB58 / RC58 / RD58)

Status (2026-10-09): runs the firmware repo's R58 firmware (the released
asm build and the C/asm hybrid) on emulated P8E and P8N processor cards
with a CU53AN or CU58AF handset, and on the RB58VY's L8M board (below);
its scenario and differential tests are in the firmware repo
(`tests/r58/`). Hardware facts: the firmware repo's `notes/hardware.md`
(P8x) and `notes/rb58vy.md` (L8M).

## Layers

| Layer | Files | Notes |
|---|---|---|
| CPU | `z80.c` | Instruction-stepped, exact T-states, all undocumented opcodes and flags (MEMPTR, SCF/CCF Q). Counts M1 cycles per step. **Passes zexdoc and zexall** (`make zex`, ~75 s). About 600 M T-states/s bare. |
| Chips | `pio.c`, `sio.c`, `pit.c`, `daisy.c` | Z80 PIO (mode 3 bit-control interrupts, runtime direction changes), Z80 SIO (async; RR0 status latching and ext/status interrupts, status-affects-vector, TX/RX timing at the programmed baud), Intel 8254 (modes 0, 2, 3, 4; gates tied high), IM2 daisy chain with RETI. |
| Handsets | `cu53an.c`, `cu58af.c` | CU53AN: HEF4555 chip-select decode, two PCF2111 (34-bit frames, latched on deselect), 8-bit HEF4035 shift chain, HEF40373 LED latch, MM74C923 keypad (DA line). CU58AF: bit-level I²C slave engine with PCF8574 ports (keypad matrix, /INT), PCF8576 LCD RAM, PCD3312 DTMF, LED and audio-control ports. |
| Board | `r58.c` | Memory map (incl. P8N SMEM NV plane and the P8E banked 0x8000 window), I/O decode, 1968.75 Hz PA0/CLK2 timebase, CLK0/1 = 4.032 MHz, ADC (last-conversion semantics), DACs, latches, watchdog, power switch → NMI, PB7 relay, FX429 (byte level), synthesizer and external serial frame capture, PC trace ring, breakpoints and watchpoints, audio edge capture of the 8254 tone pin. |
| API | `api.c`, `python/r58emu.py` | Flat C API (`libr58.so`); Python `Radio` class with symbol lookup from the linker map (`r58/build/r58.map` in the firmware repo). |
| Front ends | `main.c` (`r58emu`), `r58tui.py` | CLI smoke run; curses TUI with a headless `--script` mode. |
| Tests | firmware repo `tests/r58/` | scenarios, differential tests (`difftest.py`), RF link (`rflink.py`); `tools/r58/emuoracle.py` for bit identity |

Time is counted in 8.064 MHz crystal periods ("xt"). P8E: 1 T = 1 xt plus one wait state per M1, prefix bytes included. P8N: 1 T = 2 xt, no waits. Peripherals advance after each instruction; I/O happens at instruction granularity.

Speed (2026-10-01): ~40-55x real time (16 M Z80 instructions/s became ~30 M). The 8254 counters 0/1 are clocked lazily: their clocks accumulate until a port access, `r58api_pit` or an audio capture start/stop looks at them (the counter is then in the state per-instruction clocking gives), whole mode 2/3 periods are skipped while nobody watches the edges, and during an audio capture counter 1 is clocked every instruction for the edge timestamps. Before, 41 % of the time went to clocking counter 1 at a CW-silence reload of 4 (~1 MHz). Checked bit-identical against the old library over P8E/P8N scenarios (CPU, memory, events, audio edges, tones) with the firmware repo's `tools/r58/emuoracle.py`. The rest is the Z80 core and the daisy chain (skipping the chain walk while interrupts are disabled gained nothing).

## Fidelity evidence

- The firmware's own P8E/P8N detection (it times NOPs against the 8254) picks the right card.
- DTMF tone pairs and a complete AX.25 frame with a valid FCS decode from the emulated PWM tone pin on both cards. With the wrong wait-state model (0 or 2 waits on P8E, 1 on P8N) no valid frame decodes, so the timing check is real (`test_wrong_wait_model_breaks_aprs`).
- The emulated LCD contents equal the firmware's `segments[]` RAM after every frame.
- Synth R/N/A values match values computed independently from the firmware source, for example 433.500 MHz → R=1024, N=325, A=1.
- The firmware's SAnE procedure runs end to end: menu, powers itself down through PB7, re-powers.

## Several radios

The firmware repo's `tests/r58/rflink.py` links R58s at FX429 byte level: it
steps them in lockstep and forwards each packet a radio sends to the
others while its transmitter is on, its TX frequency is their RX
frequency, and they are not transmitting (one packet at a time per
receiver, at 1200 bit/s). Its `tests/r58/test_remote_config.py` uses it for remote
configuration end to end, including an operator on the released firmware.

## Known limits and assumptions

| Item | Assumption | Source of uncertainty |
|---|---|---|
| Watchdog timeout | 0.52 s (`wd_timeout_s`), from the P8N manual; LOCAL disabling it is not modelled | P8E not documented |
| Hook polarity (PA1) | 1 = lifted (`hook_offhook_level = 1`, since 2026-10-01; was 1 = on cradle) | assumed, not measured: the handset connector gives HK = 0 in the holder (R58 service manuals), the P8N block diagram labels PIO A1 "_HK", v3_Z's hook interrupt and OH5NXO's R58bis (`iomap_P8x.h:91`) read 1 as lifted; v3_Z's repeater-sitter check read the opposite (fixed in the firmware). Flip the default back if a real radio disagrees |
| Daisy chain | PIO before SIO | manual + P8E block diagram |
| FX429 IRQ | edge on SIO A DCD per event (shared with hook change, per manual) | 8254 OUT2 on DCDA not modelled |
| FX429 modem | byte level only: TX bytes logged as events, RX packets injected with `modem_rx()` | no bit-level FFSK audio |
| RX audio | not modelled; squelch/RSSI are ADC inputs set by the host | |
| CTCSS DSP decoder input (0x80xx bit 0), FX465, 8254 CLK2 rewire | not modelled | |
| CCIR decoder | nibble on PA7..4 settable (`set_ccir`) | |
| DTMF decoder (multiboard) | byte at 0x80xx settable (`multiboard()`) | |
| 8254 modes 1 and 5, BCD | not implemented (gates tied high on the board) | |
| SIO | async only; no sync/SDLC modes, no parity/framing errors | |
| P8E window at 0x8000 | EPROM0 top 16 KB when OUT2.RS=1, EPROM1 bank when RS=0 (only if an EPROM1 image is loaded; else the multiboard) | read from the P8E schematic, unverified on hardware |
| P8N memory | SMEM NV plane; RS/RA14/RA15 window per manual; PB0 second NV copy not modelled | |
| Output-latch polarities (LEDs, backlight) | 1 = on | |
| CU58AF keypad matrix | follows the firmware's `keytbl_cu58af` | the manual gives no key-to-matrix map |

## L8M (RB58VY system logic), 2026-10-08

`R58_L8M` (`card=L8M`, `r58emu -p l8m`): the older one-board logic of the
Mobira RB58VY. Sources: the RB58VY service manual chapter 11 (the firmware
repo's `reference/huolto-ohjeet/RB58VY_Huolto-ohje.ocr.txt`), OH5NXO's
`iomap_L8M.h` and his R58bis `boot.s`/`r58bis.c`, and the original EPROM0.

| Item | L8M (differences from P8x) |
|---|---|
| Clock | 4.032 MHz, no waits (as P8N); 8254 CLK0..2 all 4.032 MHz |
| Memory | 0000-7FFF EPROM0 (27C256); 8000-BFFF EPROM1 half picked by PB4 (S/L, its A14); C000-FFFF RAM, or with PB5 (SMEM) low the NMC9817 EEPROM over the whole area: A9..A0 from the bus, A10 = PB0 (2 KB chip, A11 unused). Writes complete at once, so data polling passes on the first read pair. A 64 KB image loads as EPROM0 + EPROM1 (`r58_load_rom`; the firmware repo's `make -C r58 l8m`) |
| I/O | decoded from A6..A4 only: 00 PIO, 10 SIO, 20 8254, 30 DAC (TPC = RFC), 40 ADC, 50 "OUT 0", 60 "OUT 1", 70 watchdog |
| 0x50 latch | DP, CLK (shared by synth and handset), /SRE, /STE, CS1, CS2, TPS, TXOFF; the CU53 gets CS1/CS2/CLK/DP as P8x OUT2 bits 4..7 |
| 0x60 latch | the P8x OUT0 audio latch (kept in `out0`) |
| ADC | IN0 RSSI, IN1 TPL (FPM), IN2 +V, IN3 RFC/TPC, IN4 TRPL (RPM), IN7 SQ (`l8m_adc[]`) |
| PIO | PA1 SLOCK (TX synth lock, read 1); PB0 EEA10, PB4 S/L, PB5 SMEM outputs |
| SIO | DCDA = /HK (RR0 DCD set while on hook, OH5NXO's `SA_ONHOOK`); TXRXCB = 8254 OUT0 (155 kHz at count 26); FX419 FFSK modem on channel A in sync mode: **not modelled** |
| Synth | S8M: MC145156, 19-bit frames SW (2), N (10), A (7), R = 1024 by its RA pins; RX loads on an SRE rising edge, TX on a /STE falling edge. 40/41 prescaler (`prescaler=40` in `Radio`) |
| Watchdog | port 0x70; stopped while LOCAL is grounded (manual) |
| Tone pin | 8254 counter 2 (`tone_ctr`); audio capture follows it |
| NV | `r58_nv_block()`: the EEPROM (first 2 KB of the 4 KB block) |

Tests (`make test-l8m`, `tests/l8m/`, 7 tests, firmware fetched by `make refs`):
- EEPROM window and LOCAL vs watchdog with hand-made programs.
- OH5NXO's R58bis built for L8M (2014): boot display, keypad, setup menu,
  a 6 m frequency (his L8M defaults: 50..52 MHz TX, 45 MHz IF) giving
  TX VCO 50.5125 MHz and RX VCO 95.5125 MHz, TX keying, no TX out of band.
- The original Nokia EPROM0: on a blank EEPROM it copies its default
  parameter list into both 1 KB blocks (as the manual describes, ~15 s),
  then the scheduler starts task 4 at 0x98A3 in **EPROM1, which was never
  dumped** (tasks 3, 4, 8, 9 and 11 of 16 start at 0x8000..0xBFFF). Without
  it the original firmware cannot run past start-up; the display stays on
  its lamp test.

The firmware repo's own firmware built for L8M (`make -C r58 l8m`, a
64 KB image) runs too: `tests/r58/test_l8m.py` there (8 tests: boot
from the EEPROM, 6 m synth and TX, 12.5 kHz raster, keys keep TXOFF, setup
menu, EEPROM restore after a supply cut, background sync, warm start).

Not modelled: FX419 and SIO sync mode (no FFSK packets), the CCIR decoder
is as on P8x, MBUS (SIO B), EEPROM write timing, the TX timer IC25.

## Debugging

```python
r = Radio(ROM, LST, nv=nv)
r.breakpoint("tx_on")             # by symbol or address
r.watchpoint("digidx")            # stop on RAM write
r.run(5)                          # -> 'break' / 'watch' / 'time' / 'off'
r.symbolize(r.cpu()["pc"])        # 'tx_on+0'
[r.symbolize(p) for p in r.trace(32)]   # last PCs
r.step(10)                        # single instructions
r.events                          # WDRESET, TX_ON/OFF, SYNTH, MODEM_TX, MBUS_TX, ...
r.set_cpu(hl=0x8000, de=1)        # write registers (af bc de hl ix iy sp pc)
ret = r.call("set_bank", af=0x0100)   # push PC, jump: as if a CALL were executed
```

Watch out: a zeroed NV image contains zeroed hook "scripts". After the boot-time hook edge the firmware "types" eight `0` keys. Blank `cfg_onhook_script` / `cfg_offhook_script` (0xFF), or run SAnE; the test fixture does both.
